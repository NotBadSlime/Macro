# YSR 锁帧模块

> 2026-10-13：本文中的 KY3/内存版说明属于历史方案，当前 KY3 和 Fufu 卡片已改用配置通道。安装、恢复和版本限制以 [解帧器配置目标卡片](unlocker-target-cards.md) 为准；YSR 通道不变。


动作面板的“锁帧模块”包含两组不同的控制方式：YSR 共享内存控制，以及现有 RTSS 锁帧。

- **YSR 开启锁帧**：默认目标 117 FPS。添加后点击序列卡片，可以修改 1–1000 的目标帧率；编辑面板也显示当前连接读取到的帧率。
- **YSR 关闭锁帧**：恢复该次开启前读取到的帧率，不需要填写恢复数值。重复开启只更新目标值，不覆盖原值。
- 播放结束、强制停止和异常清理时也会尝试恢复。尚未开启时关闭是无操作。
- 原来的 `ysr.fps.toggle` 宏仍可导入，首次切到目标值，再次切回原值。

先通过 YSR 解帧器正常启动游戏。MacroStudio 直接使用用户提供的 `fps_toggle.py` 协议：名为 `6F83E7C5-A59D-B27D-3BBE-7D67BA1B4D5B` 的共享内存，字节偏移 8 为 int32 帧率；开启期间每 50 毫秒刷新目标值。无需 Python，无需额外运行 `fps_toggle.py`，也不依赖提供源码的本机 E 盘路径。不要同时运行另一份帧率切换脚本，否则双方会反复覆盖帧率。

若显示未检测到 YSR，请先打开兼容此协议的解帧器和游戏。访问被拒绝时，使用与解帧器相同的权限运行 MacroStudio。该模块不负责启动、注入或安装解帧器，也不兼容采用其他共享内存名称/布局的版本。

关闭恢复的是开启前的原帧率，不代表把游戏帧率设成 0 或无限。当前帧率显示的是 YSR 配置上限，并非游戏实测 FPS。

## 内存锁帧（同一模块，不注入 DLL）

“锁帧模块”包含 **内存开启锁帧** 和 **内存恢复帧率**，与 YSR、RTSS 放在一起。
不需要 KY3、FpsHotkeyExt.dll、RTSS 或注入任何 DLL。先正常启动原神，再使用卡片。

- 开启卡片默认 117 FPS，可编辑 0–1000，0 写为 999，表示不限帧。
- Macro 定位游戏内的 int32 帧率变量，直接 ReadProcessMemory / WriteProcessMemory；每 50 毫秒刷新目标。
- 首次开启保存当前值，重复开启只更新目标。恢复卡片、宏结束、强制停止和异常清理会停止刷新并写回开启前的值。
- 宏快捷键使用 Macro 原有的触发设置；单独建一个“内存恢复帧率”宏即可绑定恢复键。
- 当前帧率显示的是游戏目标上限，不是实测渲染 FPS。

地址按游戏文件中的完整特征码定位，检查 setter/getter 指向同一个变量、运行时两处调用位置一致、函数体为原指令或已识别的可执行跳转、目标在主模块内且可写。不使用固定 RVA，不修改代码，不创建远程线程，不调用游戏内部函数，不更改页保护。无法确认地址或权限不足时不写入。

请以与游戏相同的权限运行 MacroStudio；若提示访问被拒绝，可尝试以管理员运行。若系统仍禁止访问，此方式会明确失败，不绕过进程保护。多个游戏进程同时运行时拒绝选择，避免改错进程。
游戏或其他工具若持续覆盖帧率，可能与 Macro 的定时写入相互影响；测试时请停用其他帧率控制。

宏文件保存为 `memory.fps.start` / `memory.fps.stop` / `memory.fps.toggle`，字段 `toggleFps`。
之前保存的 `ky3.fps.*` 卡片自动按同一内存方式执行，不再要求扩展 DLL；`ysr.fps.*` 仍使用原 YSR 协议。
内置原生 FPS DLL 的旧源码保留用于历史参考，不再参与 Macro 本地构建、安装包构建或发布依赖。

### KY3 已改写帧率函数时

KY3 可能 hook setter/getter 的函数入口。内存版允许 E9 相对跳转和 FF25 间接跳转，检查跳转目标为可执行内存；仍须验证两处原始调用位置与游戏文件一致，以及 setter/getter 从文件推导出同一个可写变量。Macro 只读写该变量，不跟随跳转调用函数，不安装 hook，也不注入额外 DLL。未知改写仍拒绝写入。

该校验兼容已通过模拟 KY3 改写和 375 项回归测试；真实游戏中是否会被 KY3 持续覆写仍需运行验证。若成功开启后仍回到 KY3 配置的值，请在 KY3 界面关闭内置帧率覆写进行对照测试。
