# 条件调用与调度优化

## 调用语义

“调用宏”现在执行目标主流程，并启动目标自带条件。子宏的启动门控先执行，再开始主流程；时间窗口以子宏调用起点/主流程起点为基准。只有条件没有主步骤的宏会等待条件触发，需设置合理时间窗口或使用停止键取消。

子宏条件里的“停止本层”结束子宏并返回父宏；“停止本轮”和“停止本次”向父宏传递。已在调用链中激活的宏不会重复启动自身条件，以免自调用/循环调用无限增殖条件线程；自调用仍执行主流程。优先用宏 ID 标识调用链，无 ID 的旧宏按名称标识。条件调用最多嵌套 64 层。

每次播放开始解析依赖快照，检查丢失目标并缓存解析结果。运行期间修改被调用宏不会改变本次播放，下次播放生效。支持原有尾调用循环，不把循环引用一律视为错误；依赖数量最多 4096。

## 并行和轮询

并行分支使用有上限的专用工作线程，不依赖线程池调度长时间阻塞任务。两个分支准备完成后通过屏障获得同一个计划起点，不再额外增加固定 1ms。全进程并行执行名额最多 32 个，一次取得两个名额，超限明确报错；嵌套最多 8 层。播放空闲线程最多缓存 8 个，并行空闲线程最多缓存 32 个，60 秒无工作后退出。每个工作线程独占并复用可由取消信号唤醒的计时器。

像素轮询与较重的 OCR/图像识别分开设置优先级；识别线程不使用时间关键优先级，触发动作执行时再进入相应精度模式。识别超时错过旧轮询时刻后跳过追赶。

同一评估器内，图像/哈希条件共享相同区域截图，文字条件共享相同区域和语言的 OCR 结果；等待同一键的计算可取消。完成后仅保留 1ms 合并窗口，不长期缓存旧画面。不同区域或语言不混用结果。

静态条件动作按播放会话缓存执行计划；随机等待和动态条件不提前固化。图像模板采用真实 Windows PNG 解码，缓存解码与模板亮度预处理，保留精确匹配阈值，不采用近似搜索改变命中行为。

## 验证

新增测试覆盖：条件包调用、子宏三种停止范围、启动门控、依赖快照稳定性、识别并发合并、并行线程上限、静态计划缓存及真实 PNG 颜色/匹配。

图像搜索与哈希计算检查取消请求，条件包等待也可取消。

## 2026-10-13 生命周期和编辑体验更新

控制器提供 `StopAsync()`、`DisposeAsync()`；同步停止只请求取消，运行及效果恢复结束后才释放资源。停止清理期间不排队重启。每次运行具有唯一编号，界面忽略旧运行完成通知。监听后台准备根宏和子宏快照，依赖指纹未变化时不重建，失败保留原有有效版本。运行中的完整循环使用启动版本；新绑定立即供下次启动，按住运行仍由原按键松开停止。

热键在独立消息循环线程处理，急停先发取消。真正退出时等待活动运行、退休控制器、准备任务和待保存内容；超过 5 秒提示仍在停止，不强制释放使用中的资源。日志使用单写入线程和 4096 条有界队列，溢出汇总普通日志丢弃数量，错误优先，退出最多等待 2 秒刷新。

编辑统计采用树形计数和检查溢出的乘法，不展开重复。JSON 输入防抖 250ms，后台解析并丢弃过期版本；无效输入保留上次有效列表，不自动保存。保存维持 450ms 防抖，串行写入并跳过过期版本。列表复用会话内行标识和可见容器，保留选择、滚动及撤销/重做的选择状态。

断网卡片明确不调整系统时间；独立调时卡片负责调时。旧宏显式设置的偏移继续有效。

验证：383 项回归通过，另有 WPF 独立验证覆盖行复用、多选、撤销/重做、虚拟化、UI 阻塞时热键处理、按住后换绑松开、子宏变更和失败准备隔离。取消及播放测试使用假输入设备，不向实际游戏发送输入。1000 行单项修改 35 个预热后样本：P50 10.708ms、P95 16.120ms、P99 16.963ms；实际创建 10 个行容器。UI 阻塞 1 秒期间实际热键取消信号 2.935ms。百万次重复计数 0.0019ms、120 字节分配。
