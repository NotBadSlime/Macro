# 单宏执行路径优化与验证

本页保留第一轮测量。后续已完成最终版本的物理热键与 Win32/WPF 真实输入接收，并进行了固定核心五轮尾部对照，见 [单宏尾部与端到端实测](single-macro-tail-and-end-to-end-2026-10-14.md)。下文的真实接收未完成状态属于第一轮历史记录。

日期：2026-10-14。当前阶段聚焦单个预编译键鼠宏，保留暂停、取消、按住时长与输入安全语义。

## 实际改动

- 原生执行器在单宏适用场景下认领整个连续段，一条线程连续推进，不为每个批次扫描队列、获取调度锁或通知两条线程。
- 名义截止、实际按下后的最短按住时间、修饰键保持约束仍沿用原语义。控制事件或新任务到达时，通过 generation 变化退出连续段，交回已有调度器。
- 修饰键边沿在创建预编译计划时计算一次，执行阶段直接读取。
- 复用统计工作区时取消对整个提交时间数组的清零。释放依赖只引用本次已执行的前序批次，其时间戳先写后读。补充了同一计划连续复用且迟到启动的按住时长回归。
- 单宏原生均衡按实际 timer 唤醒超时量，在每次运行内将末段自旋窗口有界提高至最多 800µs；初始为 300µs。控制事件不参与学习。
- 极限定时事件保留辅助线程；只有相邻名义批次间隔≤20µs、当前有效截止已临近的密集段使用连续路径。

单宏并不要求只使用一条内部线程。首轮对照显示，极限 1ms 节奏若完全关闭辅助线程，虽然 CPU 时间减半，但 P99.9 从约 3–5µs 上升至 22–87µs，因此最终版本保留定时事件的辅助抢救。不能把这一被否决的原型结果当作最终性能。

## 基准口径

`--single-benchmark` 使用测试专用假输入回调，不向桌面发送键鼠。预热完成并创建计划后，计量一次运行；CPU 时间为测试进程的 kernel+user CPU time，wall time 包含等待完成事件。运行结束后再计算统计和写 CSV，不将导出开销计入执行时间。

1ms 节奏为五轮交替顺序、每轮 20,000 批次，每方案每档累计 100,000 样本。每轮约 20 秒，不是五轮各十分钟的完整场景验收。零等待密集段每次 100,000 批次，衡量调度吞吐；所有批次同一名义截止，因此其 P99.9 随累计执行时间增长，不作为周期抖动指标。

原始数据、基线/最终测试 EXE、日志位于工作区 `tmp/single-macro-20261014`。基线 EXE 在修改执行器前编译并保存。已有工作区修改不回退，原生产 ABI 和宏配置枚举不变。

## 本次结果

本机：AMD Ryzen 9 7945HX、16 个物理核/32 个逻辑处理器，Windows 11 build 26200，电源方案 Turbo。没有主动施加 CPU/GPU 压力，也没有证明系统完全空闲；温度和频率未锁定。极限每个新进程按原准备流程测核，不固定同一对核心，因此不能将所有最大值变化归因于某一个代码改动。

QPC 本次频率为 10MHz，0.0µs 表示采样端点落在同一 tick，不表示键鼠响应或执行耗时为零。所有最终定时样本均未观察到早于名义截止的提交、缺失或批次乱序。输入数量是测试回调的逻辑计数，未验证目标应用收到输入。

均衡的尾延迟改善有资源代价：每轮约 20 秒内，进程平均 CPU 时间从 1621.9ms 增至 9446.9ms，约从 0.08 到 0.47 个逻辑核心。极限约为 1.99 个逻辑核心，基本不变。它们是测试进程的消耗，不是全机 CPU 百分比。尚无游戏 FPS/帧时间或功耗收益结论。均衡最大迟到仍超过 1ms；极限本次零个 >1ms 事件也不是最坏时限保证。

## 可复现入口

正常回归及单宏假输入：

```powershell
.\tests\MacroHid.NativePlayback.Tests\x64\Release\MacroHid.NativePlayback.Tests.exe
.\tests\MacroHid.NativePlayback.Tests\x64\Release\MacroHid.NativePlayback.Tests.exe --single-benchmark 1 20000 1000 balanced.csv
.\tests\MacroHid.NativePlayback.Tests\x64\Release\MacroHid.NativePlayback.Tests.exe --single-benchmark 2 20000 1000 extreme.csv
```

参数依次为模式（1=原生均衡，2=极限）、批次数、间隔微秒、CSV 路径。快速路径回退开关须在进程启动前设为 `MACROHID_DISABLE_SINGLE_RUN_FASTPATH=1`；它用于隔离连续路径，不等于完整恢复优化前全部源码。

真实输入探针需要在本机交互桌面运行：

```powershell
.\tests\MacroHid.NativePlayback.Tests\x64\Release\MacroHid.NativePlayback.Tests.exe --receiver-benchmark 1 10000 1000 receiver.csv
```

探针创建自己的测试窗口，只在该窗口为前台时发送带序号的 F24 按下/抬起。等待前台最多五秒，必要时点击测试窗口；切换窗口会使后续注入停止。CSV 包含计划时间、调度时间、SendInput 进入/返回、接收回调、实际发送数量和收到次数。目标处理可能早于 API 返回，分析时用 receiver−submit_begin，不能要求 receiver−submit_end 必须非负。

本次非交互启动没有取得测试窗口前台焦点，探针在发送前中止。因此没有真实接收延迟结果，也未完成游戏/物理热键/光学响应验收。
