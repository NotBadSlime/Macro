# KY3 / Fufu 配置目标卡片（测试版）

两种卡片通过解帧器配置切换目标，不枚举游戏模块、不从外部读写游戏内存，不加载额外扩展 DLL。YSR 保持原通道，宏格式与旧卡片别名兼容。

## 每台电脑首次设置

顶部「解帧器设置」自动识别运行中的启动器，或选择启动器根目录/插件目录。路径存储在 `%APPDATA%\MacroHID\unlockers\settings.json`，不随宏传播，不限制盘符，支持中文和空格。
Fufu 使用插件旁 `config.ini`，也可选择含 `Plugins\FuFuPlugin` 的启动器根目录。当前支持 DLL SHA256：`58240C6B54A074AE6525C314B79A995ED6F614AB3626EF527EF9B88250DBBE6B`。
KY3 使用插件旁 `dll_config.ini`。先退出游戏，再点击「安装 KY3 20 毫秒补丁」，原 DLL 备份到旁边 `.macro-original.bak`。完成后重新启动游戏；「恢复 KY3 原 DLL」同样要求退出游戏。

KY3 原文件 SHA256：`0EC8DD34AB869690ACEAD919BF0AF65530DACC3DEB5788D70F9C2A0FDE44C16B`。
补丁 SHA256：`3FD1EEA553C2A99C7DD2B0B7780F81ECFFF873065BB50ED7E23D834302B585D7`。
C# 生成补丁，仅修改两个 2000 毫秒比较立即数和 PE 校验和，保留原 200 毫秒条件。用户不需要 Python 或编译器。未知/升级 DLL 拒绝修改。原版 2 秒通道须明确勾选备用模式。

## 配置与恢复

Fufu 修改 `[TargetFps] Value`，要求 `[FpsUnlock] Value` 非零；目标 1–1000，原目标恢复允许最高 100000。KY3 修改 `[Settings] targetFps`，要求 `enableFps` 非零；目标 30–1000。两者的 0 均表示 999。
首次开启保存配置目标，后续切换不覆盖原目标。恢复卡片、宏结束、停止播放和正常退出恢复原配置目标。
写入保留编码/BOM、换行、注释和其他设置，通过临时文件原子替换。相同目标不重复写盘，每个配置只允许一个 Macro 实例控制。发现其他程序修改目标时解除控制并提示，不抢写或恢复覆盖外部值。
写入前保存持久恢复记录。异常退出后下次启动，仅在当前目标仍匹配记录中的写入值或写入前值时恢复；外部修改则保留当前值并归档记录。失败保留待恢复记录，可在设置中点击「处理异常退出恢复记录」重试。

## 延迟与验证边界

界面显示「配置目标」；写入成功仍在等待解帧器应用，不是实际 FPS 测量。短时间连续切换可能合并，不承诺精确响应时间。
Fufu 当前公开源码每 100 毫秒检查文件，发现修改后等 100 毫秒再加载，通常需约 100–200 毫秒加游戏回调；这不是对安装 DLL 的实测保证，需进入游戏世界验证。
KY3 20 毫秒只是检查间隔；原 200 毫秒条件、回调频率和游戏状态仍可能影响响应。
配置格式、范围、冲突、互斥、异常恢复、路径发现、补丁备份恢复测试通过。补丁与离线副本完整哈希一致。2026-10-13 用户在本机实测确认：KY3 安装补丁后、Fufu 保持原 DLL，均能降到 60 并恢复。日志核对配置写入与恢复一致。用户随后确认：第二台电脑的 KY3 和 Fufu 也均能降低帧率并恢复，两个通道完成两台电脑的功能验证。精确响应延迟和性能影响尚未量化，继续保留测试版；验证结果仅适用于已适配 DLL 版本，不代表所有电脑、所有版本均已测试。

日志：`%APPDATA%\MacroHID\log\runtime-*.log`，顶部可「打开日志」。搜索 `[FPS] CONFIG OPEN/DLL/WRITE/RESTORE/RECOVER`、`KY3 PATCH`、`ERROR`。记录路径、DLL SHA256、原目标、请求目标和时间戳，不宣称实测 FPS 已达到。
