# 启动前门闩条件 — 设计说明

日期：2026-08-29  
状态：已确认，待实现

## 背景

现有条件序列在触发后与主序列**并行**监控，可选「暂停主时间线」。无法表达「触发后先等画面/文字条件成立，再开始主序列」。

## 目标

1. 条件可设为 **启动前门闩**：按下触发键后，先等待条件成立，再启动主序列。
2. 门闩 **只等待，不执行**「触发后执行」动作。
3. 多条门闩：**全部满足（AND）** 后才开主序列。
4. 普通条件（同时执行 / 暂停主时间线）在主序列开始后仍按现有逻辑工作。

## 非目标

- 不新开独立「启动条件」编辑器（复用条件列表）。
- 不做 OR 组合门闩（本版仅 AND）。
- 不改播放期 `macro.call` 语义。
- 本版不强制做可视化倒计时 UI（状态栏提示即可）。

## 方案

在 `ConditionExecutionMode` 增加 **`GateMainSequence`（启动前门闩）**。

## 语义

| 阶段 | 行为 |
|------|------|
| 触发 | 若存在 ≥1 条 `GateMainSequence` 条件：进入等待；否则立刻开主序列（现状） |
| 等待 | 轮询门闩条件（像素/OCR 等）；忽略其 `ThenSteps` |
| 通过 | 全部门闩成立 → 结束等待 → 启动主序列 + 激活非门闩条件监控 |
| 超时 | 若门闩配置了有效 `WindowEnd`（相对触发时刻）：超时则取消本次播放并提示；未配置则一直等（可被停止键打断） |

步骤范围（Start/End）对门闩：**等待阶段不使用步骤窗**；门闩从触发起即检测，直到满足或超时/停止。

## UI

- 「触发动作执行方式」增加：`启动前门闩（等条件后再开主序列）`
- 选中该模式时：
  - 隐藏或禁用「触发后执行」区
  - 显示短提示：「仅等待条件成立后启动主序列，不跑触发后动作」
- 条件列表徽章可区分门闩（如「门闩」）

## 模型 / 格式

- `ConditionExecutionMode.GateMainSequence`
- `.mcrx`：`executionMode: "GateMainSequence"`（与现有枚举序列化一致）
- 旧文件无此值 → 行为不变

## 运行时落点

| 组件 | 职责 |
|------|------|
| `ConditionModel` | 枚举新值 |
| `McrxParser` / `McrxSerializer` | 读写 |
| `MacroPlaybackExecutor` | 播放前等待门闩；通过后再跑主序列与其余 ConditionMonitor |
| `ConditionDirectivePanel` | 下拉项、隐藏 Then 区、列表展示 |
| 测试 | 枚举/序列化、等待后开主序列、超时取消、Then 不执行 |

## 错误处理

| 情况 | 处理 |
|------|------|
| 用户停止 | 退出等待，不跑主序列 |
| 超时 | 提示并结束本次播放 |
| 门闩 OCR/区域无效 | 与现有条件校验一致；无法检测则等待失败或沿用现有错误提示 |

## 验收标准

1. 仅含门闩条件的宏：触发后主序列步骤不立即执行，条件满足后才执行。
2. 门闩条件的 ThenSteps 在等待通过时不被执行。
3. 门闩 + 普通并行条件：主序列开始后普通条件仍可触发。
4. 无门闩时行为与 1.3 一致。
5. 相关测试通过。

## 决策记录

- 交互目标：宏一开始先等条件再跑主序列。
- 门闩角色：只当门闩，不跑触发后动作。
- 多门闩：AND。
- 实现：扩展 `ConditionExecutionMode`，不另建宏级字段。
