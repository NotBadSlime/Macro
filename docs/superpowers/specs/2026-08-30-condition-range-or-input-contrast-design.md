# 条件步骤/时间范围 OR 与输入框对比度

日期：2026-08-30

## Summary

条件编辑里「执行步骤范围」允许为空，并与「时间范围」改为真正的 OR：任一时段命中即监视，中间空档不监视。同时加深时间范围与期望文字输入框的边框/背景对比，暗色主题下更易辨认。

## Goals

- 步骤范围可清空（「不限」），不再强制绑定步骤
- 步骤范围与时间范围逻辑为 OR（方案 A：两段各自监视）
- 至少一端有效；两端都空时校验失败并提示
- 时间范围 ms 框、期望文字框边框更明显
- 列表徽章与提示文案反映 OR 语义

## Non-Goals

- 不改条件类型、执行方式、TimeBase 三种基准
- 不拆成两个独立条件项/两个监视器实例
- 不改主序列步骤编辑器的像素窗字段样式（除非共用全局 TextBox 样式一并受益）
- 不在本线做安装包/发版说明长文

## Current behavior

- 新建条件默认绑到第一步；步骤下拉不能空
- `ApplyConditionTimeWindow` 把步骤推算时段与显式 `WindowStart`/`WindowEnd` **取交集（AND）**
- 暗色下 `ControlBorder`（`#3C4552`）与面板背景接近，ms/文字框像纯文本

## Design

### 1. 输入框可见性

- 在条件面板对 `WindowStartMsBox`、`WindowEndMsBox`、`ExpectedTextBox` 使用加强样式（或提高全局 TextBox 边框对比，使条件字段明显）
- 暗色：更深背景或更亮边框；聚焦仍用现有 `FocusRing`
- 校验失败时保持红色边框覆盖

### 2. 步骤范围可空

- 开始/结束下拉首项：`（不限）`（本地化）
- 清空两端 → `StartStepPath`/`EndStepPath` 为 null，`StartStepIndex`/`EndStepIndex` 用哨兵 `-1`（或等价「无步骤范围」约定），序列化时省略或写空路径
- 仅一端清空时：视为无步骤范围（与两端空相同），避免半开区间歧义
- 新增条件：若已有步骤可选，仍可默认第一步；用户可改为不限

### 3. OR 监视语义（方案 A）

有效约束：

| 步骤范围 | 时间范围 | 行为 |
|----------|----------|------|
| 有 | 无 | 仅在步骤推算时段内监视 |
| 无 | 有 | 仅在 TimeBase + WindowStart/End 内监视 |
| 有 | 有 | 两段都监视；空档不监视 |
| 无 | 无 | 无效：UI 报错，播放前拒绝或跳过并诊断 |

实现要点：

- 停止把步骤窗与显式时间窗 `Max`/`Min` 并成单段
- `ConditionMonitor`（及门闩等待路径）在「步骤时段集合 ∪ 显式时间窗」上判断：当前 elapsed 落入任一段则轮询/可触发；仅当所有段都已结束才停
- 多段时：等待进入下一段（sleep 到最近未来起点），段外不误判为超时结束，除非已超过所有段的 end
- 触发后动作仍只跑一次（现有触发语义不变）

### 4. UI 文案

- 步骤范围旁提示：可空；与时间范围满足其一即监视
- 时间范围旁保留 TimeBase 说明
- 列表 `RangeBadge`：无步骤时只显示时间基准；有步骤显示步骤标签；两端都有时用「或」连接简写

### 5. 兼容

- 旧宏：两端步骤都有 → 行为从 AND 变为 OR（有意变更；两段重叠时与旧交集接近，不重叠时监视变宽）
- mcrx：无步骤时不写或写空 `startPath`/`endPath`；`startStep`/`endStep` 可用 `-1` 或省略（解析兼容旧文件）

## Test plan

- UI：不限选项、清空步骤、两端空校验、输入框样式冒烟（文件断言）
- 运行时：仅步骤 / 仅时间 / 两者不重叠（两段都触发机会）/ 两者重叠 / 两端空拒绝
- 门闩条件同样遵守 OR
- 回归：既有仅时间窗、仅步骤推算的用例仍通过（按新语义调整断言）

## Out of scope follow-ups

- 可视化时间轴画两段区间
- 把 OR/AND 做成用户可切换模式
