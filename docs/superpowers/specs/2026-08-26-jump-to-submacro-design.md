# 从调用宏步骤跳转编辑子宏 — 设计说明

日期：2026-08-26  
状态：已确认，待实现计划

## 背景

主宏序列里大量使用「调用宏」嵌套子宏。当前只能在宏库里手动点开子宏，编辑路径长、容易找错。需要从序列步骤直接进入对应子宏的编辑序列，并能返回上一宏。

## 目标

1. 在序列中对「调用宏」步骤：**双击**或**右键 → 进入子宏**，跳转到该子宏的编辑序列。
2. 跳转前**自动保存**当前宏（复用现有切换保存逻辑）。
3. 提供**返回上一宏**（导航栈），编辑完子宏可回到来路宏。
4. 宏库选中项与编辑器当前宏保持同步。

## 非目标

- 不新开独立编辑窗口。
- 不改变播放期 `macro.call` 语义。
- 不做完整面包屑路径条（仅「返回上一宏」即可）。
- 不在本次改导出/导入逻辑。

## 方案

采用 **方案 A：序列面板事件 + MainWindow 导航栈**。

- `StepSequencePanel`：识别调用宏步骤，处理双击与右键「进入子宏」，发出导航请求。
- `MainWindow`：解析引用、自动保存、切换宏、维护返回栈、提供「返回上一宏」入口。

## UI 行为

### 进入子宏

| 入口 | 行为 |
|------|------|
| 双击「调用宏」步骤行 | 进入该步骤引用的子宏 |
| 右键菜单「进入子宏」 | 同上；仅当选中单个「调用宏」步骤时显示/启用 |
| 其他步骤类型 | 双击保持现有行为（如打开行内编辑）；右键无「进入子宏」 |

### 返回上一宏

- 序列面板工具区增加「返回上一宏」按钮（或等价控件）。
- **仅当返回栈非空时可见/可用**。
- 点击后：自动保存当前宏 → pop 栈 → 加载上一宏，宏库选中同步。

### 跳转流程

1. 从选中步骤取出 `MacroCallStep.Macro` 引用字符串。
2. 在当前宏库快照中用 `MatchesReference`（Id / Name / Aliases）解析目标项。
3. 解析失败：状态栏提示（如找不到子宏），不跳转、不清栈。
4. 目标已是当前编辑宏：状态栏提示已在该宏，不重复入栈。
5. 成功：`SaveActiveEditorBeforeSwitch` 自动保存 → push 当前宏 Id → `LoadMacroFromLibrary(目标 Id)`（含宏库选中同步）。

### 返回栈失效

以下情况**清空返回栈**，避免指到已删除或不相关宏：

- 用户在宏库手动点选其他宏（非本功能触发的导航）
- 新建宏并切入编辑
- 当前栈中某 Id 对应宏已被删除（返回时发现缺失则清空并提示）

从本功能「进入 / 返回」触发的切换**不**清栈（进入时 push，返回时 pop）。

## 边界

- 循环、像素条件 Then、条件序列 Then 内的「调用宏」均可进入（只要步骤类型是 `MacroCallStep`）。
- 多选步骤时：不进入；右键不显示「进入子宏」。
- 拖拽与双击冲突：沿用现有拖拽阈值；真正的双击手势才触发进入（不把拖拽松手当成进入）。
- 锁定宏：仍允许进入查看/编辑策略与现有「打开宏」一致（若保存受锁限制，沿用现有保存失败提示）。

## 组件落点

| 组件 | 职责 |
|------|------|
| `StepSequencePanel.xaml(.cs)` | 双击检测、右键菜单项、发出 `OpenReferencedMacro` / 暴露返回按钮点击 |
| `MainWindow.xaml(.cs)` | 导航栈、解析、保存、加载、返回、状态栏提示 |
| `Strings*.resx` | 「进入子宏」「返回上一宏」、找不到/已在该宏等文案 |
| `tests/MacroHid.Core.Tests/Program.cs` | 源码断言 + 如有纯逻辑的解析/栈辅助则可单测 |

## 错误处理

| 情况 | 处理 |
|------|------|
| 引用无法解析 | 提示，不跳转 |
| 自动保存失败 | 提示，不跳转、不 push |
| 返回时上一宏已不存在 | 提示，清空栈，停留当前宏 |
| 已在目标宏 | 提示，不 push |

## 验收标准

1. 双击「调用宏: 3aww」进入名为/别名为 `3aww` 的子宏序列。
2. 右键「进入子宏」行为与双击一致。
3. 跳转前未保存修改会写入库（与宏库切换保存一致）。
4. 「返回上一宏」回到进入前的主宏；可多层进入并逐级返回。
5. 在宏库手动改选其他宏后，返回按钮消失（栈已清）。
6. 相关测试通过。

## 决策记录

- 交互：双击 + 右键都要。
- 未保存：自动先保存再跳转。
- 返回：要导航栈 + 「返回上一宏」。
- 实现路径：方案 A（事件 + MainWindow 栈），不新开窗口、不在面板内偷偷换文档。
